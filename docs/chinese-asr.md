# 离线中文语音跟随

在“设置 → 语音跟随 → 默认语音识别语言”中选择“中文”，或在稿件详情中单独选择中文。选择“自动”时，会忽略标题和方括号备注，并根据正文中的汉字、拉丁字母和西里尔字母数量选择模型。

中文模型为 sherpa-onnx 的 WenetSpeech 14M 流式 Zipformer，使用 CPU 推理。编码器和连接器为 int8，解码器为 fp32，总计约 31 MB。模型在构建时下载并打包进 APK；语音识别不需要联网，网络权限用于已配置的在线稿件库。

## 从识别结果到滚动

- 模型输出汉字，不是拼音。稿件与识别结果都按单个汉字拆分：“大家好”和“大 家 好”得到相同的匹配单元。
- 标点不参与匹配；全角拉丁字母和数字进行兼容归一化。温度和百分数按中文读法展开，例如「36.5℃ → 三十六点五摄氏度」「25% → 百分之二十五」，也兼容 °C、℉、°F、‰ 及前置温标读法。其他外语词及独立数字标记仍按跳过规则处理，不把它们当作定位证据。未加入繁简转换；正常跟随的局部对齐可使用系统离线单字拼音辅助，但不把同音当作完全相同的汉字。
- 文字显示、加粗、标题和方括号备注保留原有位置映射。中文短语模式可以在没有空格的句子中换行，保留原标点；备注不参与朗读匹配。
- 中文使用单句锚点和字符窗口对齐。正常跟随允许从锚点逐字推进；跳转需要连续字串和足够的匹配比例，减少常见单字造成的误跳。
- 中文 partial 替换前一个临时结果，final 提交锚点；英语保留历史合并流程。更新后的 token 索引驱动悬浮窗和全屏提词器的滚动与高亮。
- 中文按字计算速度和时长，英语按词计算；真实对齐不使用提前量，视觉高亮独立按平均语速预测。中文界面统一显示“字词”，设置相同数值时，中文与英语的实际朗读节奏会有差异。
- 稿件热词取连续的 2–4 字片段，使用 sherpa-onnx 的 `cjkchar` 编码。中文不读取英语模型使用的 BPE 词表。

## 语音重新开始

中文语音跟随中说「欧了重新开始」或「欧了重新来」，精确识别后立即回到稿件开头并取消待确认回退。口令不参与稿件匹配，连续 partial 和 final 不重复重启；口令后同一段话中的正文可继续正常跟随。开启稿件热词时，也会加入两个口令以提升识别机会。暂停和非语音模式不会执行口令。为避免误触，不对口令进行模糊匹配。

正常向前跟读保留短错词、漏字和加词的容错与正确结尾恢复，不要求整句完全相同；后续内容正确且足够唯一时继续推进。

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

可使用模型仓库自带的 `test_wavs/0.wav` 复核流式识别。参考文本为“对我做了介绍那么我想说的是大家如果对我的研究感兴趣”。普通解码和开启热词的解码都应能输出中文，随后由相同的逐字跟踪器定位到稿件末尾。Android 上的麦克风并发、功耗和实际朗读体验仍需在手机上验证。


## 按朗读进度定位当前字

参考 [Storm-Teleprompter-Plus 的字符对齐引擎](https://github.com/html5syt/Storm-Teleprompter-Plus/blob/f345ae2f79d7222ce444664c9ca0e8b89f7e79de/lib/services/asr/alignment_engine.dart)。中文直接消费 sherpa-onnx 的单句 partial/final：短 utterance 从已确认锚点对齐，长 partial 只匹配新增部分或修订的短结尾，final 提交锚点；修订中的短结果不会让游标回退。暂停恢复、重新开始和手动点字同步重置锚点。

将温度与百分数展开为匹配用的虚拟汉字，过滤其他标点、舞台备注及中文模型不支持的外语和独立数字后，保留与原稿 token 和 UTF-16 偏移的映射；不会改写显示文本。同一个符号的多字读法完成后，才推进到下一个显示 token。短 utterance 保留原有逐字容错；长 partial 按新增字数推进 3–8 字窗口，单次局部对齐最多一次编辑。短锚点在加载时按标点和系统分词边界建立，记录字符起止、权重与惰性缓存的拼音；普通片段 4–8 字，标点和末尾可形成更短片段，显示稿件不被改写。正常局部搜索从指针前 8 字到后 28 字，重复位置需要更强的上下文；三字或脱离已确认上下文的弱短锚点需两次识别确认。虚词占比高的片段不作为独立锚点。

局部 DP 同时保留零编辑和一次编辑路径，汉字相同最优；单字同音替换用较低权重，只可作为周围准确汉字的辅助证据。拼音由 [Android 系统 Transliterator](https://developer.android.com/reference/android/icu/text/Transliterator) 的 [ICU Han-Latin 转换](https://unicode-org.github.io/icu/userguide/transforms/general/) 提供，忽略声调并缓存；转换不可用时回到汉字匹配。单字读音不提供完整的多音字语境消歧，不做任意近音扩展。无需新增模型或网络请求。

显式跟随阶段包括正常跟随、低置信等待、静默保持、回退确认和重新锚定。连续三次低置信输出后等待 400ms，期间收到的强目标由定时器到期确认；三字锚点仍须第二次识别。跟丢超过两秒后，可用末尾准确短语在前方 64 字内重新锚定。麦克风判为静默超过 1.5 秒时不执行跳转，取消旧候选；恢复发声后继续从当前位置对齐，不以噪声驱动基线滚动。

回读取识别结果末尾配置的 4–8 字，默认 5 字，在当前进度前 100 个匹配用汉字内搜索；最多允许一次替换、插入或漏字，编辑距离相似度 `1 - 编辑次数 / max(识别字数, 稿件片段字数)` 必须 ≥80%。因此 4 字中替换错 1 字仅为 75%，不会通过；5 字错 1 字可通过。位置必须唯一，同等匹配优先当前或前方。连续两次匹配的识别更新（重复的相同 partial 不计数），或同一结尾及位置稳定 450ms 后才回跳；长句和 final 也不能跳过确认。稳定时间由滚动定时器检查，无需等待识别器再次输出。设置入口为「设置 → 语音跟随 → 回退匹配字数」，保存立即生效并取消旧候选。暂停、切换模式、手动定位及重新开始也取消待确认回退。回跳后剔除当前识别片段中已经错误的前缀，继续逐字跟随。缩短的临时识别不能充当重读确认；相同回调只能累计稳定时间，不增加匹配次数；同样匹配的当前或后续句优先保留向前跟随。

真实识别进度与视觉预测独立。语音模式从可靠识别推进的时间差自动估算语速，不使用手动 WPM、倍率或目标时长；至少积累 120ms 的有效间隔后测量，近期速率采用 70% 新值、30% 旧值平滑，较快适应朗读节奏变化。跳读、回读、重启和长停顿重置语速；没有可靠推进时不以背景声音驱动预测。识别回调即时发布视觉进度，100ms 定时器仅作连续更新及确认，不再额外等待一次定时器才启动视觉跟随。

渲染采用无背景卡拉 OK 文字变色：未读白色，当前和预测区青色（#8EC4BA），真实已读灰色（#747E7D）。已读边缘按 130ms 插值在字符内部逐步扫过，回读与重启用 180ms 恢复；青色预测与灰色已读边缘分开，预测不改变真实已读数量或 tracker。原稿偏移、符号、扩展汉字、备注及强调格式保持有效；备注保留独立颜色，不计入朗读。

解除当前行和可见行对预测的截断，预测与跟随可向下一行推进；中文仍最多提前六字，英文由提前上限约束，预测不越过语句边界。朗读期间保持前进，句末、停顿、暂停及确认回读后平滑回收；保留渐隐、手动浏览及回退提示。定速和声音模式单独使用手动字词/分钟及 0.50x–3.00x 倍率，界面不再提供速度基线或目标时长设置。

点击悬浮窗设置中的“调整大小”显示窗内 48dp 大把手，分别调整宽高，点“完成”收起；把手向内避开屏幕边缘手势，窗内移动把手在横竖屏均可移动位置；各方向分别保存大小与位置，不改变文字字号。设置支持左、中、右对齐。语音识别仅提供中文、英文，构建时清除旧俄语模型资产。

`ChineseRetakeTest` 覆盖错词前缀、短句、漏错字、流式确认、回跳后继续跟随、重复句、临时识别缩短、范围限制与符号位置映射。`ChineseReadingsTest` 覆盖符号、整数、小数、百分比、前置温标、单字分隔输出、显示偏移、手动定位、错读恢复及误跳防护。`ChineseAlignmentTest` 覆盖逐字定位、final 锚点、partial 修订、漏字错字、重复句、确认回读、标点备注及扩展汉字偏移、手动定位和重新开始。MIT 署名及完整许可见 `THIRD_PARTY_NOTICES.md`。


悬浮按钮仅在已开启悬浮提词且设置允许时显示：点击切换提词层显示/隐藏，隐藏时保留识别会话；长按退出悬浮提词并移除按钮。

中文模式共用六种返回开头口令：「欧了重新开始」「欧了从新开始」「欧了重新来」「欧了从新来」「欧了从头开始」「欧了返回开始」。热词及示例说明同步使用此列表；允许输出中的空格和标点，保留“欧了”前缀及精确字词约束，同一次 partial/final 只重启一次。
